# Midterm / 2026 — Data Journalism Project Roadmap
Updated November 12, 2026 (America/New_York)

## Completed
1. **Collect original polls and review supplemental data.** Original PollResults archive: 1,354 question records, 146 race IDs. Curated master: 1,357 records, 148 race IDs, three additions. Candidate-only enrichment: 1,583 records, 149 race IDs; unverified rows must not enter accuracy metrics. See `analysis/2026_poll_master_audit.json` and `analysis/2026_candidate_enrichment_audit.json`.
2. **Refresh reported results.** Updated `data/results.json` from civicAPI for all 470 contests; archived previous version in Git history; audit `analysis/2026_results_refresh_audit.json`. Source called 460/470 as of the refresh, not certification. Approximately 8,119,502 additional votes recorded across contests versus November 5. **Reporting-percent values declined for many races; do not treat these as stable completion indicators.**

## Required next steps
3. **Define eligible polling observations.** Only 2026 general election and polls with fieldwork ending by Nov. 2. Choose either a 21-day or 30-day final window (pre-register the choice), likely-voter versus registered-voter preference, and how to handle question variations and independents. Explicitly exclude known fabricated surveys and separately flag partisan/internal surveys. Audit original poll IDs, question IDs, sponsor and pollster before averaging. The archived 2026-11-01 snapshot is incomplete for fieldwork ending Nov 1–2; supplements collected later can be historical data if fieldwork and release dates are evidenced, but do not claim the later retrieval was a pre-election freeze.
4. **Compute defensible race polling averages.** One observation per independent survey per matchup/population, no double-counted RCV variants. Calculate `D - R` margin from original candidate percentages. For each race expose polls used, date range, source links, included/excluded count, estimate, and a sensitivity estimate excluding partisan polls. Mark no-data/insufficient-data clearly. Do not substitute forecasts for polling.
5. **Validate final result margins.** Merge original sources and updated civicAPI data by stable race ID. Candidate-specific matching is vital for Alaska and independent/no-major-party races; multi-seat, RCV, and partisan-cross-endorsement cases require explicit rules or omission. Track unofficial vs certified, vote count collection time and state source URLs. Freeze a comparison cutoff date and update only in versioned snapshots.
6. **Calculate polling error.** `signed_error = final_two_party_DminusR_margin - final_poll_DminusR_margin`; `absolute_error = abs(signed_error)`. Distinguish % of polled races with positive error, mean signed error, mean absolute error, median error and winner-call accuracy. Do not claim an industry-wide effect from heavily polled races alone.
7. **Test data quality.** Unit tests for denominator, sign convention, representative district with R/D/independents, duplicated surveys, unmatched candidate, missing polls and wrong dates; manual reconciliation for at least 10 races with original releases and state results.
8. **Create visualizations.** Race selector + election margin vs poll average (dumbbell) with exact source links; sortable race-error table; House vs Senate error distributions; aggregate national summary with the denominator visible. Offer missing poll coverage map/table separately.
9. **Write story and methodology.** Opening: New York Times October fake-poll disclaimer and November 2 weighting uncertainty. Report what was measured; do not assert fake polls caused legitimate polling error or that weights caused party-wide errors without method-specific evidence. Include its Nov 4 retrospective as a counterexample to premature causal inference.
10. **Independent adversarial review and accessibility.** Separate agent checks methodology and potential partisan framing; check keyboard, screen readers, responsive views and uncertainties. Validate the complete pipeline is reproducible offline using committed JSON and normal library tools.
11. **Publish.** Commit code, data, sources, audit and methodology with attribution and license separation; run all JavaScript and Python tests; review deployment. Keep source snapshots in Git history. Mark results unofficial until certified and refresh audit when updated.

## Data status warning
`analysis/2026_race_results_baseline.csv` was generated from Nov. 5 results; use it only for historical comparison. The most recent source is `data/results.json`. The 470-race file is **not 470 polled races**. Do not calculate error for unpolled or unverified rows.

## Recommended MVP boundary
Finish stages 3–8 for races with adequately sourced polls before extending to 470 rows, pollster-level rankings, or causal claims about industry methodologies.
